# Project Instructions

Build the application described in the technical assessment PDF provided to you.

## Core Requirements

Use the following project architecture and technology choices:

* Split the project into:

  * `frontend/`
  * `backend/`
* Frontend: **React**
* Backend: **Python + FastAPI**
* Data storage: **JSON file**
* AI/LLM integration: **Google Gemini API**
* Do not use a production database such as PostgreSQL or MySQL.
* Keep the implementation simple and appropriate for a junior-level technical assessment.
* Do not over-engineer the application.

## Project Structure

Create a clear structure similar to:

```text
project/
├── frontend/
├── backend/
├── progress.md
└── README.md
```

You may modify the internal structure of `frontend/` and `backend/` if there is a good reason, but keep the frontend and backend clearly separated.

## Progress Tracking

Create a `progress.md` file in the project root.

Use this file to track:

* What has been completed
* What is currently being worked on
* What remains to be implemented
* Important implementation decisions
* Any known issues
* Any setup/configuration steps that still need to be done

Update `progress.md` whenever you complete a meaningful task.

The purpose of this file is to allow you to understand the current state of the project if you continue working on it in a later session.

Before starting new work, check `progress.md` and inspect the existing code so that you do not unnecessarily repeat completed work.

## Backend

Use FastAPI.

Implement the required functionality from the assessment, including APIs for:

* Getting tasks
* Updating task status
* Analysing a task with AI

The API structure can follow the assessment examples:

```text
GET /tasks
PATCH /tasks/{id}/status
POST /tasks/{id}/analyse
```

You may structure the endpoints differently if there is a clear technical reason, but keep the API simple and RESTful.

### Task Model

Each task should contain:

```text
id
title
description
priority
status
createdAt
```

Valid statuses:

```text
NEW
IN_PROGRESS
COMPLETED
```

Valid priorities:

```text
LOW
MEDIUM
HIGH
```

The backend must validate task status values and reject invalid values.

Use JSON as the persistent storage mechanism.

Keep the JSON data easy to inspect and modify manually during development.

## AI Integration

Use the **Google Gemini API** for the AI analysis functionality.

The flow should be:

```text
React Frontend
      ↓
FastAPI Backend
      ↓
Gemini API
      ↓
Structured AI Result
      ↓
React Frontend
```

The AI analysis should return structured information similar to:

```json
{
  "category": "DOCUMENT_REQUEST",
  "priority": "HIGH",
  "summary": "Customer needs to provide their latest payslip.",
  "recommendedAction": "Request the missing payslip."
}
```

Design the Gemini integration so that the backend controls the API call rather than exposing the API key to the React frontend.

### API Keys

Do NOT hardcode API keys.

Leave clear comments/placeholders in the appropriate configuration files showing exactly where I need to provide my Gemini API key.

For example, use an environment variable such as:

```text
GEMINI_API_KEY=
```

Include comments explaining where the key needs to be added.

Do not commit any real credentials.

## AI Failure Handling

The application must handle Gemini/API failures gracefully.

If the Gemini API:

* fails
* times out
* returns an unexpected response
* cannot be reached
* returns invalid structured data

the backend should return an appropriate error response and the frontend should display a useful error message.

The application must not crash because of an AI/API failure.

## Frontend

Build a simple React interface.

Visual design is not a major priority. Focus on functionality, usability, and clean code.

The interface should allow the user to:

* View the list of tasks
* Filter tasks by status
* See task priority
* See task creation date
* Change the status of a task
* Analyse a task with AI
* View the AI analysis result
* See loading states
* See appropriate error states

Keep the UI straightforward. Do not spend excessive time on animations or unnecessary visual features.

## Testing

Include at least **one meaningful automated test**.

Prefer testing an important backend behaviour, such as:

* Valid task status is accepted
* Invalid task status is rejected
* AI failure is handled correctly

Choose the test that provides the most useful coverage for the implementation.

Make sure the test can actually be run using a clearly documented command.

## Development Process

Work incrementally.

1. Inspect the current project directory before making changes.
2. Read `progress.md` if it exists.
3. Plan the next small set of tasks.
4. Implement them.
5. Run the relevant tests/checks.
6. Fix any problems you find.
7. Update `progress.md`.
8. Continue until the assessment requirements are complete.

Do not assume that generated code is correct. Verify it by running the application, tests, API requests, or other appropriate checks.

If something fails, diagnose and fix the underlying issue rather than simply documenting the failure.
